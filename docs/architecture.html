The system in one line

defense-foundations is not a running service — it is an evidence-gated curriculum operating system. It takes a single external date authority, turns it into scheduled work, turns work into artifacts, turns artifacts into verifiable evidence, and lets only that evidence open a phase gate. Everything in the diagram exists to protect that one conversion from being faked.

The overall flow

Read the diagram top to bottom. Data flows downhill through nine bands:

  • External authority — the Aegis Nexus vault (01_Daily/_Phase Config.md) is the sole hard-date source. This repo never invents a date; it mirrors one. A Calendar manifest supplies issue definitions, and the day envelope supplies capacity.
  • The active boundary — the sole Phase 0 cutover at 2026-09-04 00:00 PDT is a real architectural component, not a note. Everything crossing it has its counter set to zero. Prior work stays audit-valid history but earns no active credit.
  • Projection — TIMELINE.md, README.md, and progress/README.md are read-only downstream copies of the vault's dates plus the rules that govern status.
  • Curriculum plane — 13 phases, of which exactly one (P0) is powered. P1–P12 sit dormant and undated by design; their 18–24 month bands are competency envelopes, not dates. The Agent Engineering Sprint is a bounded side module, not a phase.
  • Supply — learning materials, the Rustlings drill state, and six research queues feed the execution loop. They are inputs, never outputs.
  • The main loop — Python stage ↔ Rust stage → bounded AI-agent stage when allowed → manifest-owned support/research work. Python and Rust share one weekly pair_cycle_id while retaining independent proof; degree commitments may split the language blocks across days.
  • Artifacts — the Phase 0 deliverable is one shared Python/Rust file-statistics contract plus a separately tracked, non-gate manual agent policy/evaluation surface attached to that same contract. Both implementation halves are currently stubs.
  • Validation — local pytest/ruff/ cargo test/clippy transcripts are the only accepted proof today, because .github/ does not exist yet. The CI node is drawn as a hollow, un-powered box for exactly that reason.
  • Ledger and gate — current local issues carry acceptance tests; the baseline checkpoint is 2026-09-26, independent readiness is reviewed 2026-10-15, and the final capability decision is 2026-10-30, with the horizon ending at 23:25 PDT.

The two things worth staring at

The rejected path. The magenta dashed line from the overlay boundary stops short of the gate and terminates in an ✕. The manual Project 0 agent overlay and daily research paper are scheduled; any future sampler would require an exact manifest amendment. Those non-gate artifacts can never satisfy the Python/Rust/Linux/Git exit gate. That severed edge is the single most load-bearing design decision in the repo.

The remediation loop. A PARTIAL / REMEDIATE verdict routes back up into Primary Build, and a written extension loops back into the gate itself. Neither one resets the anchor. The system has no path that silently restarts the clock. Only the active boundary at the top defines the current denominator.

Terminal nodes

Two nodes are dead ends on purpose. The mobile PWA's localStorage drains into a NOT EVIDENCE terminator — quick notes and untouched legacy checkbox state can never flow back into the ledger. And the CI node has no inbound power at all until the Week 1 workflow is committed under issue P0-W1-L.

What the moving dots are

Each dot is one unit of data actually travelling that edge: a date assignment, an issue record, a command transcript, a gate verdict, a zeroed counter, a rejected overlay artifact. Authority layer

The vault file 01_Daily/_Phase Config.md lives outside this repo and is the only writer of hard dates. Current identity is a literal string — FINAL-2026-09-04-0000-PHASE0 — which makes “which denominator am I counting against?” answerable. Superseded reset administration is not carried in the live timeline.

Curriculum plane

curriculum/README.md is the index; each phases/NN-*/README.md holds focus, topics, materials, evidence target, current baseline, and exit gate. The promotion rule is the state machine: a phase becomes active only after prerequisites are demonstrated, a concrete output is selected, and promotion is explicitly authorized. Reaching a date does not promote anything.

Two orderings coexist deliberately: the execution order (P0→P12) and the capability order (foundation → measurement → perception → systems/edge → robotics/navigation → HMT/agents → decision/coordination → assurance → capstone). The cross-phase build chains (e.g. Rust telemetry service → ROS 2 bridge → distributed mesh telemetry) are the edges between those two views.

Execution loop

Encoded in TIMELINE.md and the P0 README as distinct Python ↔ Rust → bounded AI-agent stages on one weekly Project 0 pair_cycle_id. The manifest reports gate-foundation, bounded agent-overlay, paper/endr, and overhead loads separately. The agent stage is non-gate and cut first when proof lags; its scheduling separation does not create an independent artifact lane or a new percentage bucket.

The Rust and Python halves are drawn at low elevation on purpose. Box height in this diagram encodes how much real implementation exists, so the artifact band is visibly the thinnest part of the system.

Validation layer

The accepted evidence set is a runnable project, command transcript, test result, benchmark, experiment table, demo recording, or a README with reproducible instructions. progress/README.md adds the defense-specific bar: an artifact is not interview-grade until it can state, in writing, latency, failure modes, false-positive rates, resource usage on the target device, and tradeoffs.

The evidence-source rule is enforced as a hard branch: before .github/workflows/ exists, cite local output with the exact command line; only after the workflow is committed may a GitHub Actions run URL be cited. No document may cite a run URL today.

Ledger

docs/ISSUES.md holds current acceptance keys for the launch, weekly work, gates, research, and endr. Each carries an objective, an acceptance test, required evidence, dependencies, a evidence boundary and a status. Dates and scheduled identities come from the active manifest; historical keys remain historical.

Gate mechanics

The September 26 baseline checkpoint diagnoses foundation gaps; the October 15 review assesses independent readiness. The October 30 final review reads the ledger and emits a written promote, remain, or extension decision. Exit criteria: Python + Rust CLI built from a problem statement, first 50 Rustlings exercises, shell/Git without notes, one repo meeting the README evidence standard, and FizzBuzz/file-I/O/CLI from scratch.

Mobile PWA (read-only consumer)

mobile/app.js loads the generated docs/aegis-phase0-projection.json and renders its nine calendar windows, plus phases[] (14 rows including the O0 non-gate overlay row). getCurrentWeek() resolves today against generated start/end values and clamps to first/last. The app exposes no task-completion writer or evidence percentage.

Prior reset-scoped checkbox keys remain untouched as legacy, non-evidentiary browser state, but the current app neither reads nor writes them. Scratch notes deliberately retain their historical key so no genuine text is erased. sw.js is cache-first for the app shell and network-first for the generated projection, with the last verified response retained as an offline fallback in defense-foundations-mobile-shell-v3. It uses skipWaiting() + clients.claim() and old-cache eviction on activate. A hash-checked generator and drift validator now replace the former hand-mirrored date path.

Boundaries the code enforces

  • Overlay proof → Agent Engineering Sprint tracker, never the P0 gate.
  • endr company work → tracked in endr/Aegis; cannot satisfy or delay a gate.
  • Mobile quick notes and legacy checkbox state → never repo evidence.
  • Reset administration, dashboard edits, Calendar work → not curriculum evidence.
  • Graduated projects (project-aegis, CASEset, GUARDEN) → their own repos; defense-foundations-lab is retired.

Notable structural risks

  • Dual date sources. Dates are duplicated across the vault, TIMELINE.md, README.md, progress/, phase READMEs, ISSUES.md, and mobile/app.js — seven hand-synced copies of one authority.
  • Un-powered CI. Every "deterministic check" claim currently rests on manually pasted transcripts.
  • Declared-but-absent test paths. pyproject.toml points at a tests/ directory that does not exist, so a green pytest run today proves nothing.
