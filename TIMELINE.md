## Active scope

Foundations control the gate:

- Python and small CLIs.
- Rust, Cargo, and Rustlings.
- Linux shell and development tools.
- Git/GitHub workflow.
- Tests, CI, README quality, reproducibility, and repository hygiene.

Python, Rust, AI-agent concepts, battlefield AI, and warfare study run in
parallel. Agent and research work are non-gate. A bounded Project 0 agent
exercise can produce a policy/test/trace but cannot substitute for Python or
Rust proof. It has no shell, network, browser, connectors, Git writes,
deletion, installation, secrets, persistence, self-modification, autonomous
execution, multi-agent/swarm, MCP, RAG, LangGraph, or consequential capability.
PyTorch training, YOLO, ROS 2/Nav2, MARL, and robotics depth remain later
competencies until their gates open.

## Phase 0 plan — paired file-statistics CLI

Resume the oldest unmet criterion in each language. Python owns one explicit
file-statistics contract; Rust independently proves parity on identical
fixtures. A pair cycle closes only when both implementations have an observed
result or an exact blocker and next command. Scheduling never waives
per-language proof or creates catch-up debt.

Use one primary teaching source per track and official documentation for
implementation reference. Start with targeted beginner instruction, then
apply concepts to Project 0 and record the exact resume point. Watching alone
grants no credit. The private plan owns course reservations.

Reaching a checkpoint never activates P1 automatically.

## Evidence boundary

Historical work remains genuine Git history but is excluded from current-period
credit unless independently verified under the active authority. Earlier CLIs,
course work, papers, and agent study may inform diagnosis but do not pre-check
current trackers. Reset administration is not curriculum evidence.

Until `.github/workflows/` exists, acceptable CI-adjacent proof is saved local check/test output with the exact command. A GitHub Actions URL may be cited only after the workflow is committed under `P0-W1-L`.

## Later phases

P1–P12 and specialization modules remain `not started` and undated. A failed or delayed P0 gate produces a scope cut or written extension, never another implied completion or automatic advanced-lane ramp.
